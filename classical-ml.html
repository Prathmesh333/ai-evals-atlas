Chapter 03 / Foundations

Evaluate prediction models beyond LLMs

Evaluate classification, regression, ranking, clustering, forecasting, and decision policies.

Learning level 10–203 min read + practice1 diagram · 1 exercise

Match the prediction to the decision

AI evaluation also covers models that never produce text. A classifier assigns a label or class probability. A regressor predicts a number. A ranker orders candidates. A forecasting model predicts future values. Each output needs a different evaluation contract.

For a demand forecast, predicting the usual value can be useful even when rare peaks remain difficult. For an anomaly detector, the rare event might be the entire purpose. Choose the decision and its error costs before selecting an aggregate metric.

A baseline should match that decision. Compare a forecast with a seasonal naive forecast. Compare a classifier with majority-class and simple linear baselines. Compare a recommender with a popularity baseline. A complex model should justify its added operational cost.

Understand regression and probability metrics

Mean absolute error averages absolute prediction errors. Root mean squared error takes the square root of the average squared error. Squaring makes large errors contribute more. Report the target unit and inspect errors by target range.

For actual values [2, 4, 8] and predictions [3, 4, 6], absolute errors are [1, 0, 2]. Mean absolute error is 1. Root mean squared error is √(5/3), about 1.29. Neither value states whether the error is acceptable for the application.

ROC-AUC evaluates ordering across classification thresholds. A precision-recall curve often makes rare-positive tradeoffs easier to inspect. Select the operating threshold using validation data, then report performance at that threshold. Ranking quality, calibration, and decision quality are separate properties.

Cross-validation without leakage

K-fold cross-validation fits a model repeatedly while holding out a different fold each time. Fit preprocessing inside each training fold. Scaling or selecting features on the full dataset can reveal information from the held-out fold.

Use group-aware splits for related subjects and time-aware splits for forecasting. Nested cross-validation separates hyperparameter selection in inner folds from evaluation in outer folds. Fold scores are related estimates, not a collection of independent experiments.

A forecasting test should reproduce the information available at prediction time. Evaluate each horizon separately and use rolling origins where appropriate. Backfilled records or features calculated with future data can create excellent historical scores that cannot be reproduced in deployment.

Ranking, clustering, and policies

Evaluate a recommender on the candidate set users would actually face. Retrieval recall, ranking quality, novelty, and user outcomes measure different properties. Logged clicks reflect prior exposure as well as preference, so offline ranking results can be biased.

For clustering, internal separation metrics describe geometry under a selected representation. They do not prove that clusters are useful categories. If external labels exist, use them with a clearly stated purpose and check stability across samples.

For reinforcement-learning policies, measure return over multiple seeds and environments, including constraint violations. A simulator result applies to that simulator. Off-policy evaluation from logs needs assumptions about action coverage and the logging policy; it is not equivalent to a randomized deployment test.

Try it yourself

Choose a classification task and a forecasting task. State the prediction unit, baseline, split rule, metric, and deployment threshold for each.

Can you standardize the entire dataset before cross-validation?

Not when standardization learns statistics from the data. Fit it inside each training fold so the held-out fold does not influence the transformation.
