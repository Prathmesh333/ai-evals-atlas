Chapter 16 / Advanced systems

Evaluate retrieval and agents

Test evidence, tool use, final state, and consistency across attempts.

Learning level 70–753 min read + practice2 diagrams · 1 exercise

Separate the retrieval pipeline

Retrieval-augmented generation, or RAG, retrieves evidence before producing an answer. Test the document index, retrieval, reranking, context construction, and answer generation. A failure at an early stage can make later correctness impossible.

Create questions with known supporting documents. Measure retrieval recall, answer correctness, and citation support separately. Include questions whose answers are absent. The expected behavior for those cases should be explicit.

Test stale documents, contradictory evidence, duplicate passages, and inaccessible documents. A document the user cannot access should not become available merely because a retrieval tool finds it. Keep access-control checks in the system evaluation.

Agents change state

An agent can use tools across multiple steps. Evaluate the resulting state, not only the final message. For a file-editing task, inspect the files and run relevant tests. For a booking simulation, inspect the final booking record.

Reset the environment between trials. Pin dependencies and tool responses where possible. Record tool calls, returned observations, state changes, elapsed time, and the stop reason. Traces help explain failure, but a plausible trace does not replace an outcome check.

Define budgets for steps, tokens, time, and tool calls. Report task success together with budget use. More attempts or more tools can improve results without changing model weights.

Distinguish discovery from reliability

Pass@k asks whether at least one of k attempts succeeds. For n sampled attempts with c successes, a common estimator is 1 − C(n−c,k)/C(n,k), with n ≥ k. This estimates success within a sampling budget under its assumptions.

Pass-all-k asks whether all k attempts succeed. Under independent identical success probability p, the probability is pᵏ. Tasks differ in difficulty, so aggregate task-level measurements rather than applying one pooled p blindly.

Use repeated trials for stochastic systems. Report the distribution across tasks, not only the best trial. Anthropic's public agent-evaluation guidance distinguishes tasks, trials, graders, and traces, and emphasizes checking outcomes alongside transcripts.

Try it yourself

Design a simulated calendar task with a success assertion, a no-duplicate assertion, a reset procedure, and a tool-call budget.

An agent says it saved a file. Is that enough to pass?

No. Inspect the expected file and its contents. The final message is a claim about the state, not proof of that state.
