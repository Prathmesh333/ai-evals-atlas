Chapter 05 / Build a model

Build your first small model

Train a real character model on a CPU, then measure held-out performance.

Learning level 20–303 min read + practice1 diagram · 1 exercise

Start with a model you can inspect

The included Python lab trains a character bigram language model from scratch. It learns the probability of a character given the previous character. The model is small enough to inspect without a GPU or an API key.

A bigram model cannot follow instructions or reason through a problem. Its purpose is to make training and evaluation concrete. Counts are learned parameters. Additive smoothing assigns some probability to unseen character transitions.

Use text that you have permission to process. Prepare separate training, validation, and test files. Remove exact duplicate documents before splitting. The sample corpus is original, synthetic teaching material. It is too small for claims about language ability.

Run the experiment

Download or clone this repository. Install Python 3.10 or later. Run python labs/tiny_lm.py from the repository root. The default run reads the included sample files. It fits several smoothing values and selects one using validation loss.

The script evaluates the selected model once on the test file. It reports negative log-likelihood, perplexity, and an unseen-character rate. It also generates a short sample and saves a JSON report with file hashes.

Compare the bigram against a unigram baseline. A unigram predicts each character without using the previous character. If the bigram performs worse, inspect the data size and smoothing rather than assuming the implementation failed. Context only helps when its estimates are reliable.

Interpret the result

Read the generated text, but do not use an attractive sample as your main metric. Sampling is variable and easy to cherry-pick. Held-out loss measures how much probability the model assigns to the test sequence.

Repeat the experiment with your own document splits. Keep the test file fixed while exploring settings on validation data. Report both the selected settings and the selection process. If you repeatedly inspect test results, create a new final holdout.

Check failure cases. Unseen characters map to an explicit unknown symbol. A high unknown rate means the training vocabulary does not cover the evaluation data. Report that rate beside perplexity so the compressed vocabulary does not hide the problem.

python labs/tiny_lm.py

Try it yourself

Run the lab on two different text domains. Train on one domain and test on the other. Explain the change in loss and unknown-character rate.

Why does the lab choose smoothing on validation data?

Choosing it on test data would adapt the model to the final measurement. Validation supports selection while the test split estimates the selected model's performance.
