Chapter 10 / Build evaluations

Build and validate your graders

Combine deterministic checks, human review, and model judges.

Learning level 60–653 min read + practice1 diagram · 1 exercise

Use the simplest valid grader

A grader converts an output or final state into a score. Prefer a deterministic check when the requirement is deterministic. Examples include valid JSON, an exact numerical result, a schema, or a database state assertion.

Normalization is part of the protocol. Removing whitespace can be acceptable for a short answer but invalid for indentation-sensitive code. Write tests for the grader itself, including wrong outputs that look superficially correct.

Separate parsing failure from semantic failure. Both can count as task failure, but they need different fixes. Store raw outputs so you can audit the extraction and grading logic.

Use model judges carefully

A model judge can evaluate open-ended criteria that are difficult to encode. Give the judge a narrow rubric with examples. Request a structured score and a short evidence reference. Do not assume an articulate explanation makes a score correct.

Blind model identities where practical. Randomize answer order for pairwise comparisons. Test sensitivity to length, tone, formatting, and instructions embedded in the answer. Treat candidate text as untrusted data, never as judge instructions.

Calibrate the judge against independently labeled examples. Measure disagreements by failure type and score band. Reserve a human-labeled holdout for grader validation. A judge that matches humans on easy cases can still fail on the cases that determine release.

Audit the evaluator

Pin the judge model, prompt, rubric, and parsing code. Re-run calibration after a judge update. Otherwise a score change can reflect a grader change rather than a system change.

Use human review for ambiguous cases and important failure modes. Give reviewers the evidence needed to assess the rubric. Track disagreement and adjudication rather than forcing an artificial consensus.

A hybrid design can use schema checks first, factual checks next, and human review for disputed answers. Avoid averaging unrelated dimensions into one opaque score. Report correctness, support, and style separately when they serve different decisions.

Try it yourself

Write a three-level rubric for a grounded answer. Include one example that sounds confident but cites evidence that does not support its claim.

Why should a candidate answer not be allowed to give instructions to the judge?

The candidate answer is the object being evaluated. Following its instructions would let the evaluated system change the scoring procedure.
