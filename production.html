Chapter 28 / Operate and improve

Monitor deployed systems

Connect offline experiments to real usage and detect regressions after release.

Learning level 95–983 min read + practice1 diagram · 1 exercise

Offline and online evidence

Offline evaluation uses a fixed or sampled test dataset. Online evaluation measures behavior in a deployed product. The two answer different questions because users, traffic, and surrounding systems can change.

A shadow run processes copied requests without controlling the user-visible outcome. A canary release exposes a limited portion of traffic to a candidate. An A/B experiment randomly assigns eligible users or requests under a planned design.

Choose the randomization unit to avoid interference. Repeated requests from one user can be correlated. A user-level intervention often needs user-level analysis. Define outcome windows and exclusions before examining results.

Monitor useful signals

Track task success where labels are available, user corrections, escalation, refusal, invalid outputs, latency, and cost. A proxy such as thumbs-up feedback can be biased by who responds. It should not be treated as complete ground truth.

Monitor input distribution and slice volume. A change in language mix can change aggregate performance without a model update. Compare both within-slice metrics and overall metrics.

Collect only the traces needed for the purpose and apply the relevant access and retention rules. Redact or avoid unnecessary personal data. Privacy controls should apply to evaluation logs as well as product storage.

Close the feedback loop

Turn confirmed production failures into reviewed regression cases. Avoid copying sensitive requests directly into a public dataset. Create a safe abstraction when the original content cannot be retained.

Keep a rollback path for material regressions. Record the deployed configuration, incident timeline, affected slices, and corrective action. Re-test the fix on the original failure and related cases.

Refresh evaluation data as the workload changes. Keep a stable historical suite for comparisons and a current suite for present relevance. Version both so a change in the test population does not masquerade as a model improvement.

Try it yourself

Define a deployment dashboard for a support assistant. Include one user outcome, one safety signal, one latency metric, and a rollback trigger.

If the overall score drops after the language mix changes, did the model necessarily regress?

No. The task distribution may have changed. Compare performance within each language slice and check whether the model or system configuration changed.
