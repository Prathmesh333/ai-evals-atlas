Chapter 14 / Advanced systems

How frontier labs evaluate

Separate public evidence, engineering patterns, and undisclosed details.

Learning level 80–853 min read + practice1 diagram · 1 exercise

What public documents establish

Frontier labs publish selected system cards, benchmark results, research reports, and safety frameworks. These sources describe parts of the evaluation process. They do not reveal every training dataset, internal test, or release discussion.

OpenAI's April 2025 Preparedness update describes capability assessment, safeguards reports, and a Safety Advisory Group that reviews residual risk. Treat that page as a dated policy source. A framework describes an intended process; it does not independently verify every implementation.

Google DeepMind's public Frontier Safety material links capability thresholds to evaluation and mitigation. Its framework has changed over time. Read the dated version cited in a model report before interpreting a threshold or comparing decisions across releases.

A useful engineering synthesis

A practical evaluation program can use several layers: frequent development checks, broad capability suites, application tests, targeted risk assessments, and deployment monitoring. This is a synthesis for this handbook, not a claim that every lab has the same pipeline.

Development checks help researchers detect regressions early. Broader suites measure a wider set of behaviors. Targeted assessments investigate specific consequential capabilities or failure modes. Deployment monitoring tests whether offline findings transfer to actual use.

A model release also changes the surrounding system. Tool permissions, context construction, sampling, and safeguards affect results. Evaluate the deployable configuration and preserve evidence that links a decision to that configuration.

Elicitation and external scrutiny

Capability elicitation means testing conditions that help a model display an ability: suitable prompts, tools, examples, or budgets. A weak setup can understate capability. An unusually generous setup can overstate expected product performance. Describe both the assistance and the cost.

Independent evaluation can add different task designs and expertise. Access restrictions still affect what external evaluators can test. Distinguish independent measurement from a lab's self-reported result.

Do not infer secret recipes from a leaderboard. Exact frontier training mixtures, some internal tests, and deployment deliberations remain undisclosed. You can reproduce public protocols and engineering principles without pretending to reproduce a proprietary program.

Try it yourself

Read one system card. Extract the evaluated model version, tool access, task source, metric, sample size, and stated limitations.

Does a published safety framework prove that every release followed it exactly?

No. The framework describes a process. Evidence about a particular release requires its reports, evaluated configuration, and any independent assessments.
