Chapter 23 / Advanced systems

Training and evaluation at scale

Understand compute, data pipelines, distributed training, and experiment control.

Learning level 85–903 min read + practice2 diagrams · 1 exercise

Scale changes the bottlenecks

Large training runs require a data pipeline, distributed compute, checkpoints, and monitoring. A fast model implementation cannot compensate for a pipeline that starves accelerators of data. Measure input throughput and accelerator utilization together.

Data parallelism distributes batches across replicas. Tensor parallelism splits operations across devices. Pipeline parallelism splits layers. Parameter and optimizer sharding reduce per-device memory. Each method introduces communication and scheduling costs.

Mixed precision reduces memory and can improve throughput. It also changes numerical behavior. Track non-finite losses and unstable gradients. A stable short run is not proof that a long run will remain stable.

Budget compute and data

For a rough dense-transformer pretraining estimate, compute is often approximated as 6ND floating-point operations, where N is parameter count and D is training tokens. This approximation omits important architecture and implementation details.

A billion-parameter model trained on 20 billion tokens gives about 1.2 × 10²⁰ FLOPs under that approximation. Divide by sustained throughput, not advertised peak throughput, for a rough time estimate. Include evaluation, checkpointing, failures, and data preparation separately.

Scaling-law studies relate loss to model size, data, and compute under specific experimental conditions. Their fitted relationships are not universal hardware purchasing rules. Use pilot runs to estimate your own bottlenecks and quality trend.

Keep experiment identity intact

Assign each run an immutable configuration and dataset manifest. Store checkpoint identifiers and evaluation artifacts. A dashboard point should lead back to the exact model, data, and scoring code.

Evaluate checkpoints on a stable development suite. Reserve a final holdout for decisions that justify its use. If many researchers repeatedly optimize against one test set, that set becomes part of the development process.

Production training systems also need recovery procedures and data governance. This handbook explains public concepts and a small runnable path. Building a frontier training organization requires infrastructure, specialist review, and resources far beyond the included labs.

Try it yourself

Estimate 6ND for a 100-million-parameter dense model and 2 billion tokens. List five costs that the estimate excludes.

Why is peak hardware throughput a poor training-time estimate?

Real runs lose time to communication, memory access, data loading, checkpointing, and other overhead. Use measured sustained throughput for the workload.
