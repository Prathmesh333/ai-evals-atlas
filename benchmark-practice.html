Chapter 11 / Build evaluations

Run public benchmarks correctly

Read benchmark protocols and reproduce results without comparing incompatible runs.

Learning level 65–703 min read + practice1 diagram · 1 exercise

Choose a benchmark for a reason

A benchmark samples a particular ability under a particular setup. MMLU tests multiple-choice knowledge across subjects. HumanEval tests generated code with executable checks. SWE-bench uses software issues in repositories. These results answer different questions.

Read the task format, metric, split, and exclusions. Check licensing and execution requirements before downloading a dataset. A benchmark name alone does not identify its exact version or protocol.

Use the benchmark directory to select candidate tasks. Add your own application dataset because a public benchmark rarely matches your product's complete workload. Avoid describing any single rank as a universal intelligence score.

Freeze the run specification

Record the model revision, tokenizer, chat template, prompt, number of examples, decoding settings, output budget, tool access, and task revision. Include the evaluation harness version and hardware.

For multiple-choice tasks, scoring option likelihoods differs from generating an answer letter. Length normalization can also change rankings. Compare results only when the answer extraction and scoring methods match.

EleutherAI's evaluation harness supplies reusable task implementations. Its current documentation describes run subcommands and separate backend extras. Follow the documentation for the exact installed version rather than copying an old command without checking it.

Audit surprising results

Run a small subset first and inspect the complete input and output. Check whether few-shot examples fit the context window. Confirm that the model receives the intended chat format and that answer extraction finds the intended answer.

A perfect score can indicate leaked labels or a broken grader. A near-zero score can indicate formatting failure. Inspect cases before attributing either result to model capability.

Publish the run configuration and per-case results when licensing and privacy permit. If you cannot share the data, describe the sampling and scoring protocol clearly. Report failed requests and excluded cases with their reasons.

Try it yourself

Choose two published results for the same benchmark. Compare versions, prompts, tools, inference budgets, and metrics before comparing the numbers.

Are two results comparable just because both say MMLU?

No. Check task version, prompt, few-shot setup, answer scoring, model revision, and evaluation code. Differences can change the result.
