Chapter 04 / Foundations

Tokens, transformers, and generation

Follow text through a language model and understand what its loss actually means.

Learning level 15–203 min read + practice2 diagrams · 1 exercise

Predict the next token

A tokenizer converts text into token identifiers. A token can represent a character, part of a word, a word, or a byte sequence. The model predicts the next token from previous tokens. During training, each position supplies a prediction target.

For the sequence A B C, one target is B given A. Another target is C given A B. A causal attention mask prevents a position from seeing future tokens. Without that restriction, training would reveal the answer.

Tokenization affects sequence length and measured loss. Two tokenizers can encode the same sentence with different token counts. Compare perplexity only when tokenization and evaluation conventions are compatible.

Inside a transformer

An embedding maps each token identifier to a vector. Position information helps distinguish token order. Attention combines information from earlier positions. A feed-forward network transforms each position. Residual connections carry information through the stack.

Scaled dot-product attention uses softmax(QKᵀ / √d)V, with an appropriate mask. Q, K, and V are learned projections. The weights determine which accessible positions contribute to an output vector. They are not a complete explanation of the model's reasoning.

The output layer produces logits. Softmax converts logits to probabilities. Training commonly minimizes average negative log-likelihood of the target tokens. Perplexity is exp(loss) when the loss uses natural logarithms.

Generation changes the experiment

Greedy decoding selects the highest-probability token. Sampling draws a token from a distribution. Temperature changes how concentrated that distribution is. Top-p sampling restricts selection to a probability mass threshold.

Record decoding settings, stop sequences, context limits, and output budgets. A larger output budget can improve a reasoning result and also increase cost. Compare systems under declared budgets.

A context window limits the tokens available for a request. A large advertised window does not establish that the model uses all positions reliably. Test evidence near the beginning, middle, and end, with plausible distractors.

Try it yourself

For target-token probabilities 0.5 and 0.25, compute average negative log-likelihood. Exponentiate it to obtain perplexity, about 2.83.

Can you compare token perplexity directly across different tokenizers?

Usually no. Token definitions change the unit being averaged. Use a compatible tokenizer or a common normalized unit with an explicit protocol.
