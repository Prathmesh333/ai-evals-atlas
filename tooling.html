Chapter 26 / Operate and improve

Run a public benchmark with a harness

Choose evaluation tooling, run a smoke experiment, and preserve its configuration.

Learning level 90–953 min read + practice1 diagram · 1 exercise

Choose by execution needs

Use a reusable benchmark harness when reproducing public tasks and scoring conventions. Use an application evaluation tool when prompts, retrieval, providers, and regression checks are the main objects. Use an agent evaluation framework when tasks need tools, environments, and traces.

EleutherAI's language-model evaluation harness supplies task definitions and model backends. Inspect AI supplies components for model and agent evaluations. Promptfoo provides declarative application checks. These tools overlap, so choose by the experiment rather than by the number of integrations.

Compare support for custom graders, isolated execution, artifacts, concurrency, caching, and version pinning. A dashboard without exportable case-level evidence makes later audits harder. Keep the run manifest outside a single proprietary interface when possible.

Prepare a small public run

Create a virtual environment. Install the harness with the backend required by your model. Record the installed packages, model revision, dataset revision, and task name before a full run.

The command example below uses GPT-2 and a small HellaSwag subset to check the execution path. It downloads model weights and task data, so review the upstream access and license requirements. CPU execution is possible but can be slow.

A limited run is a smoke test. Its score is not a full HellaSwag result. Keep the subset flag in the report, and never compare the subset score directly with a published full-test score.

Inspect before scaling

Open several logged samples. Check the prompt, answer options, scores, and selected answer. A likelihood-scored multiple-choice task is different from asking a chat model to emit an answer letter.

If you use an instruction model, verify its intended template and task protocol. Do not apply a chat template automatically to every base model. A formatting change can alter the experiment.

After the smoke run, freeze the model and task revisions. Remove the subset limit for the intended full evaluation. Record the exact command and configuration. Public package interfaces can change, so use the documentation that matches the installed version.

Diagnose common failures

An out-of-memory error suggests reducing the batch size or choosing a model that fits the hardware. It does not justify silently truncating evaluation cases. A missing task name suggests a version or naming mismatch.

Near-random multiple-choice results can reflect weak capability, an incorrect template, or scoring mistakes. Inspect per-case evidence before choosing an explanation. Treat authentication and download failures as setup failures rather than model failures.

This notebook verifies its own small labs and provides a documentation-based harness walkthrough. It does not claim to have run a full external benchmark or measured a frontier model. Reproduction requires the listed software and data access.

Commands for this note

python -m venv .venv
# Activate the virtual environment for your shell.
python -m pip install "lm_eval[hf]"
lm-eval run --help
lm-eval ls tasks
lm-eval run --model hf --model_args pretrained=gpt2 --tasks hellaswag --device cpu --batch_size 1 --limit 10 --output_path results/smoke --log_samples
python -m pip freeze > results/environment.txt
Try it yourself

Run the ten-case smoke command if you have the required download access. Inspect two samples and record the model, task, prompt, and metric.

Can the ten-case smoke result be presented as a full benchmark score?

No. It checks setup on a small subset. Report the subset explicitly and run the specified full split for a full benchmark result.
