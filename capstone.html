Chapter 18 / Operate and improve

Your complete evaluation project

Produce a reproducible decision, from the first baseline to a release report.

Learning level 98–1003 min read + practice1 diagram · 1 exercise

Define a bounded project

Choose a task with observable success, such as extracting receipt fields or answering questions from a small document collection. Write the evaluation contract before selecting a model. Define who uses the result and what failure costs.

Create a representative dataset and a separate stress set. Reserve a final test split. Write a label guide and inspect ambiguous cases. Use stable case identifiers and document the data source.

Choose a cheap baseline and one candidate. Keep the input population and scoring protocol fixed. A comparison of two systems on different task samples needs a different analysis and is harder to interpret.

Run, inspect, and revise

Run the included evaluation lab to understand case-level scoring. Replace its synthetic cases with your task data only after updating the schema and graders. Keep the original smoke cases as implementation checks.

Inspect errors by type: invalid output, missing evidence, incorrect calculation, inappropriate refusal, tool failure, or timeout. Improve the component responsible for a repeated failure. Re-run the development suite after each change.

Freeze the candidate before the final test. Report the paired difference, uncertainty, and resource cost. If the result is inconclusive, state that conclusion. Do not invent a winner because the project needs an ending.

Publish an evidence package

Your final package should include the problem, dataset card, model or system card, run configuration, code revision, grader validation, results, and limitations. Include enough detail for another person to reproduce the experiment where access permits.

Separate measured facts from recommendations. A measured 90% on 100 synthetic tasks is a result about those tasks. A recommendation to deploy requires further reasoning about users, impact, coverage, and controls.

A strong capstone ends with a decision and its conditions. Examples include keeping the baseline, testing a larger sample, or deploying a constrained candidate with monitoring. The value is the quality of the evidence, not the size of the model.

Try it yourself

Complete the report template in labs/report-template.md. Include at least three representative failures and one unresolved limitation.

What should you do if the candidate's gain is smaller than the uncertainty?

Report the comparison as inconclusive under the current experiment. Consider a larger or better-targeted sample if the decision justifies its cost.
