Fairness, languages, and accessibility

Measure who benefits, who fails, and whether aggregate scores hide unequal service.

Learning level 75–853 min read + practice1 diagram · 1 exercise

Start from the affected people

A fairness assessment begins with the use case and affected people. Identify harms such as unequal access, inappropriate exclusion, stereotyping, or systematically worse service. One parity metric cannot represent all of these concerns.

Compare relevant outcomes across groups when collecting and using those attributes is appropriate. State why the groups matter and how labels were obtained. A protected attribute should not be inferred casually from names or appearance.

Selection-rate parity compares how often groups receive a positive decision. Equalized-odds criteria compare error rates conditional on the true label. Calibration concerns predicted probabilities. These criteria can conflict, so justify the chosen measures in context.

Look beyond one group at a time

Averages for one attribute can hide failures at intersections. Language, disability, document quality, and device constraints can interact. Report sample counts and uncertainty for each relevant slice.

Avoid declaring a small group equivalent merely because a significance test is inconclusive. A low-powered comparison can fail to detect a meaningful gap. Use effect sizes, confidence intervals, and a decision-relevant tolerance.

Fairlearn's assessment tools support disaggregated metrics and fairness measures. The tool calculates quantities; the evaluator remains responsible for choosing a valid task, population, and interpretation.

Evaluate languages as languages

Translate a benchmark only when translation preserves the construct. Wordplay, cultural references, morphology, and label balance can change. Have competent speakers review the translated tasks and acceptable answers.

Include native tasks and code-switching where those reflect users. Report language-specific success, token use, latency, and refusal. A tokenizer can increase cost for one language even when answer accuracy is similar.

For multilingual judges, check the judge's competence in each tested language. Strong agreement on English does not establish reliable grading in another language. Keep translation errors separate from model errors.

Accessibility is a system outcome

Test whether users can complete the task with their actual input and output methods. Keyboard access, screen readers, speech input, and understandable error recovery can affect success independently of model accuracy.

Measure completion, correction effort, abandonment, and human escalation for relevant user groups. Pair those outcomes with representative qualitative observations. A technically correct response can still be unusable if its format excludes the user.

Document remaining coverage gaps. Do not convert a limited set of successful accessibility tests into a claim that the system serves every disability, language, or assistive technology.

Try it yourself

Create a slice plan for a multilingual support assistant. Include language, input method, sample sizes, and one intersection that could hide a failure.

Does an inconclusive difference test prove two groups receive equivalent service?

No. The study may have too little data. Equivalence requires a defined tolerance and an analysis designed to support that claim.
