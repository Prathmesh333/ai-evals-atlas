Chapter 13 / Build evaluations

Human evaluation and preference studies

Create annotation rubrics, measure agreement, and separate preference from correctness.

Learning level 60–703 min read + practice1 diagram · 1 exercise

Choose an evaluation format

An absolute rubric scores an answer against defined criteria. A pairwise comparison asks which of two answers better satisfies the criteria. A task-based study observes whether a person can complete real work with the system. Choose the format that matches the claim.

Separate correctness, completeness, evidence support, style, and user preference. An answer can be preferred because it is confident or concise while being less accurate. A single overall preference score can hide that distinction.

Define ties and unjudgeable cases. A reviewer who lacks the domain knowledge should be able to mark a case for specialist review. Forcing a guess creates labels that look decisive but are not defensible.

Build a labeling operation

Write the rubric before large-scale annotation. Include boundary examples, common mistakes, and instructions for missing evidence. Run a pilot on a shared batch and revise unclear criteria.

Blind system identity where practical and randomize answer position. Keep the information shown to reviewers consistent. Record whether reviewers can browse, execute code, or inspect source documents because these permissions affect their judgments.

Train reviewers on the task and compensate the work appropriately. Plan breaks and assignment sizes to reduce fatigue. Keep an audit sample and use adjudication for disagreements. Avoid changing the rubric mid-study without versioning and reassessing affected labels.

Measure agreement with its assumptions

Raw agreement is the fraction of labels that match. Chance-corrected measures such as Cohen's kappa use a model of expected agreement. Kappa is (observed agreement − expected agreement) / (1 − expected agreement), and depends on the label distribution.

For more than two raters, missing labels, or ordered ratings, choose a statistic that fits the design. Report the exact method, weighting, and uncertainty. Low agreement can indicate ambiguity in the task rather than poor reviewer effort.

Inspect disagreements by category. If reviewers agree on factual errors but disagree on tone, refine the tone rubric rather than discarding the correctness labels. Preserve the original judgments and the adjudicated result.

Interpret pairwise rankings

A win rate needs a denominator and a tie policy. For example, 40 wins, 40 losses, and 20 ties can be reported as 40% strict wins or 50% with half-credit ties. State which quantity you report.

Bradley–Terry-style models estimate relative strength from comparisons. The result depends on the opponent pool, sampling, and model assumptions. It is not an absolute measure of intelligence, and it can change when the comparison pool changes.

If one user judges many pairs, account for that dependence. Test position effects and preference sensitivity to response length. The MT-Bench and Chatbot Arena paper documents concerns with model judging that also motivate careful study design.

Try it yourself

Create a rubric with three independent dimensions for a research answer. Write one tie example and one example requiring specialist review.

Is a 70% preference win rate the same as 70% factual accuracy?

No. Preference and factual correctness are different outcomes. The study must explicitly measure accuracy before making an accuracy claim.
